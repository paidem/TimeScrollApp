# TimeScroll+ 2.4.1 port validation

Base: upstream 2.4.1 (`db97c54`). Fork build: 55.1. Platform: Apple Silicon arm64, macOS 27.2.1, Xcode 27.2 (27B52).

## Performance

Optimized (`swiftc -O`) standalone harness compiled the actual `TimelineAxisLayout` implementation extracted from upstream and the port, with a synthetic model of 100,000 timestamps spaced 800 ms apart, in descending order. Each case rebuilt the layout 100 times. Port viewport: 1,000 points. The model stub provides only the fields consumed by the layout. No real data or application preferences used.

- Upstream continuous: 0.321 ms/layout.
- Port continuous: 0.372 ms/layout.
- Port fitted day: 0.467 ms/layout.

**Performance/power impact:** this sample adds approximately 0.052 ms to a continuous layout rebuild and 0.146 ms for fitted-day layout versus upstream continuous. Layouts are cached by data revision, mode, scale and viewport; rebuilds happen on changes, not each draw. These are microbenchmarks, not end-to-end scrolling or energy measurements. Day mode retains the fork's 50,000-row load cap; memory/load cost is higher than upstream's initial 1,000-row continuous page.

The previous/next-day SQL was also exercised against an in-memory SQLite database of 100,000 indexed timestamps, 1,000 iterations per direction. Both queries use the timestamp covering index. Raw measurements and query plans: [data/2.4.1-port-axis.txt](data/2.4.1-port-axis.txt).

Recovery runs only after capture failure, with delays of 3, 10, 30, 60 then 120 seconds repeatedly until capture resumes or is stopped. Normal capture adds no polling. Storage entitlement/signature checks are cached once per process, as in the preserved local improvement.

## Validation

- Debug build passed with local ad-hoc signing (`CODE_SIGN_IDENTITY=- CODE_SIGN_STYLE=Manual DEVELOPMENT_TEAM=`).
- Full Xcode test targets compiled with `build-for-testing`; hosted tests were not launched because app startup accesses production settings/storage.
- 19 tests in five suites passed in an isolated temporary Swift package using the production source and existing tests: CaptureRetryLoop, TimelineDayRange, TimelineZoomFit, TimelineTickPlanner and DayActivityCalculator. Covers retry exhaustion/replacement/cancellation, DST, midnight, empty/single-day spans, tick overlap and zoom fit.
- Day controls rendered offscreen with the actual SwiftUI view files and a synthetic model. Inspected light/dark appearance, today/older date, fitted/zoomed states. Controls occupy a separate row so they do not crowd the upstream toolbar.
- No installed app launched, recordings migrated, signing credentials changed, or release published.

Default signed build could not use upstream's Apple development team; ad-hoc compilation succeeded. Xcode reports an installed CoreSimulator version mismatch, and upstream source has existing deprecation/concurrency warnings.
